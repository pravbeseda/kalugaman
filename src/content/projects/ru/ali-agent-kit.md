## Что это

Инструмент для тех, кто пользуется несколькими ИИ-агентами сразу. Скилл — это
записанная процедура, по которой агент работает: как ревьюить ветку, как
разбирать комментарии к пул-реквесту, как проходить вопросы плана по одному.
Проблема в том, что каждый агент хранит скиллы у себя, и копии на разных машинах
и в разных агентах неизбежно расходятся.

`ali-agent-kit` делает из них **npm-пакет**: скиллы лежат в одном репозитории,
публикуются в реестр и ставятся одной командой — `npx ali-agent-kit@latest
install` — во все обнаруженные агенты сразу: Claude Code, GitHub Copilot CLI,
Codex CLI. Скилл может ограничить себя конкретными агентами — тогда в остальные
он не ставится. Обновление — та же команда; есть и `list`, `validate`,
`uninstall`, `--dry-run`. Пакет опубликован в npm и используется
мной каждый день.

Установка **атомарная**: файлы собираются во временном каталоге и подменяются
переименованием, при сбое возвращается прежняя версия, а следы убитого запуска
подбираются при следующем. Удалённые из пакета
скиллы удаляются и у потребителя, а чужие файлы не трогаются никогда — у своих
есть маркер владения, и если рядом обнаружился не наш файл, команда завершается
отдельным кодом возврата, а не молча перезаписывает.

## Скиллы

Сейчас в пакете 11 скиллов, они покрывают путь от задачи до слияния.

- **Ревью.** `ali-review-branch` проверяет локальную ветку — вместе с
  незакоммиченным — и проводит по находкам по одной. `ali-review-pr` публикует
  замечания инлайн-комментариями с пометкой `blocking` / `suggestion`, как
  обычный ревьюер: только вопросы и сомнения, без готовых исправлений, — и
  заканчивает вердиктом о готовности к слиянию. `ali-review-pr-duo` запускает
  это ревью параллельно в Claude и в Codex.
- **Работа с замечаниями.** `ali-process-pr-comments` берёт незакрытые
  замечания по одному: проверяет каждое по коду, вносит правку и резолвит тред;
  очевидные замечания ботов решает сам, спорные обсуждает. `ali-merge-pr`
  сливает пул-реквест и отказывается, пока открыт хоть один тред или упала
  проверка.
- **Решения и документы.** `ali-one-by-one` проходит открытые вопросы плана
  поочерёдно — контекст, варианты с оценкой, рекомендация, — записывает решение
  и затем реализует принятое. `ali-generate-pr-description` пишет описание
  пул-реквеста по шаблону самого репозитория, не трогая его чек-листы.
- **Автопилот.** `ali-autopilot` сам реализует фичу: план, затем цикл «шаг →
  независимое ревью субагентами → исправление», в конце — ветка и пул-реквест
  со списком принятых за тебя решений.
- **Инструкции агентов.** `ali-instructions-global` и `ali-instructions-project`
  проверяют и приводят в порядок файлы инструкций: один мастер-файл
  рендерится для Claude Code, Codex и Copilot, каждая запись — с бэкапом и
  подтверждением.
- **Crashlytics.** `ali-crashlytics-issues` переносит краши из Firebase
  Crashlytics в GitHub issues, сверяя каждый с кодом и никогда не заводя дубль.

## Стек

Чистый **Node.js** (>= 18), **ноль зависимостей** — пакет ставится как CLI и
тянуть за собой чужое дерево не должен. Тесты — на встроенном `node:test`,
в CI на Node 18, 20 и 22. Тесты проверяют и сам репозиторий: таблица скиллов в
README сверяется с тем, что пакет реально содержит, намеренно продублированные
между скиллами блоки обязаны совпадать, а весь текст — быть на английском.

Поддержка агента — это **плагин-адаптер** на один файл: идентификатор, название
и функция, которая по окружению возвращает каталоги. Новый агент добавляется
без правок ядра. Валидатор скиллов проверяет имена, frontmatter и дубли и
запускается в `prepublishOnly`, так что сломанный скилл невозможно опубликовать.

Релиз — workflow **GitHub Actions** с ручным запуском и выбором `patch` /
`minor` / `major`: версия читается из реестра, бампится только в рабочей копии и
публикуется с **provenance**, после чего создаются git-тег и GitHub
Release. В `main` при этом ничего не коммитится — ветка
остаётся защищённой, и любое изменение попадает в неё через пул-реквест.
