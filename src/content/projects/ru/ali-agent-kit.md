## Что это

Инструмент для тех, кто пользуется несколькими ИИ-агентами сразу. Скилл — это
записанная процедура, по которой агент работает: как ревьюить ветку, как
разбирать комментарии к пул-реквесту, как проходить вопросы плана по одному.
Проблема в том, что каждый агент хранит скиллы у себя, и копии на разных машинах
и в разных агентах неизбежно расходятся.

`ali-agent-kit` делает из них **npm-пакет**: скиллы лежат в одном репозитории,
публикуются в реестр и ставятся одной командой — `npx ali-agent-kit@latest
install` — во **все** обнаруженные агенты сразу: Claude Code, GitHub Copilot CLI,
Codex CLI. Обновление — та же команда. Пакет опубликован в npm и используется
мной каждый день.

Установка **атомарная**: файлы собираются во временном каталоге и подменяются
переименованием, прерванный запуск не оставляет полускилла. Удалённые из пакета
скиллы удаляются и у потребителя, а чужие файлы не трогаются никогда — у своих
есть маркер владения, и если рядом обнаружился не наш файл, команда завершается
отдельным кодом возврата, а не молча перезаписывает.

## Скиллы

- `ali-review-branch` — сравнивает текущую ветку с базовой и проводит по
  находкам по одной, а не вываливает список целиком.
- `ali-review-pr` — публикует замечания инлайн-комментариями к строкам кода
  через `gh api`, как обычный ревьюер: только вопросы и сомнения, без готовых
  исправлений.
- `ali-process-pr-comments` — берёт незакрытые замечания к пул-реквесту по
  одному: проверяет, справедливо ли каждое, обсуждает решение, вносит правку и
  резолвит тред.
- `ali-one-by-one` — проходит открытые вопросы плана поочерёдно: контекст,
  варианты с оценкой, рекомендация, — и записывает принятое решение обратно в
  файл плана.
- `ali-generate-pr-description-uc` — собирает дифф ветки в готовое описание
  пул-реквеста по корпоративному шаблону, вместе с обязательными чек-листами.

## Стек

Чистый **Node.js** (>= 18), **ноль зависимостей** — пакет ставится как CLI и
тянуть за собой чужое дерево не должен. Тесты — на встроенном `node:test`,
включая проверку самого README: таблица скиллов в документации сверяется с тем,
что пакет реально содержит, чтобы документация не расходилась с кодом.

Поддержка агента — это **плагин-адаптер** на один файл: идентификатор, название
и функция, которая по окружению возвращает каталоги. Новый агент добавляется
без правок ядра. Валидатор скиллов проверяет имена, frontmatter и дубли и
запускается в `prepublishOnly`, так что сломанный скилл невозможно опубликовать.

Релиз — workflow **GitHub Actions** с ручным запуском и выбором `patch` /
`minor` / `major`: версия читается из реестра, бампится только в рабочей копии и
публикуется с **provenance**. В `main` при этом ничего не коммитится — ветка
остаётся защищённой, и любое изменение попадает в неё через пул-реквест.
